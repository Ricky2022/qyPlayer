# 青云播放器 0.6.0 开发说明

0.6.0 做制作器的三件 P0（排序理由见 [`editor-roadmap.md`](./editor-roadmap.md)）：

1. 配乐与视频原声混音，包格式升到 0.4。
2. 转码输出的 H.264 级别过高的问题（先真机验证，再改）。
3. 草稿自动保存与恢复。

## 1. 混音

### 1.1 格式 0.4 新增字段

全部可选，缺省时行为与 0.3 完全一致。0.1 到 0.4 的包都能打开；旧播放器（v0.5.1 及更早）打开 0.4 的包提示版本不支持。

| 位置 | 字段 | 取值 | 缺省 | 说明 |
| --- | --- | --- | --- | --- |
| 顶层 | `videoVolume` | 0 到 1 | 有 `bgm` 为 0，没有 `bgm` 为 1 | 整片的视频原声音量 |
| `bgm` | `duck` | 0 到 1 | 1（不压低） | 有声视频页上配乐的增益系数 |
| `pages[].items[]` | `muted` | 布尔 | false | 这一个视频不出声；只对视频有意义 |

`bgm.volume` 原来就有（0 到 1），含义不变，现在由界面写入。

生成器写 0.4 的包时：总是写 `videoVolume`；有配乐时总是写 `bgm.volume` 和 `bgm.duck`（这样重新打开时能区分“关掉了压低”和“旧包没有这个字段”）；`muted` 只在为 true 时写。

### 1.2 增益规则

播放、预览、导出共用，都在 `packages/core/src/timeline.ts`。

名词：

- 有效原声音量 V：`videoVolume` 的取值，含上表的缺省规则。函数 `videoVolumeOf`。
- 有声视频页：V 大于 0，且页里有一个素材同时满足：是视频、`hasAudio` 不为 false、`muted` 不为 true。函数 `isSoundPage`。

视频原声增益（`local` 是页内时间），函数 `videoSoundGain`：

```
videoGain = V × (muted ? 0 : 1) × videoAudioGain(local, 页时长)
```

`videoAudioGain` 是原有的每页首尾 0.1 秒淡入淡出，没有改。

配乐增益（`t` 是影片时间）：

```
d(t)      = t 到最近一个有声视频页时间段的距离（秒）；在段内为 0；全片没有有声视频页时为无穷大
duckAt(t) = duck + (1 − duck) × min(1, d(t) / 0.5)
bgmGainAt = bgm.volume × 开头淡入 × 结尾淡出 × duckAt(t)
```

对应函数 `bgmDuckAt`、`bgmFadeGainAt`（音量与首尾淡入淡出）、`bgmGainAt`（两者相乘）。

效果：配乐在有声视频页开始前 0.5 秒开始压低，页一开始就已经到位；页结束后 0.5 秒恢复。相邻两个有声视频页之间不回升。

例子：照片 0–4 秒、视频 4–10 秒、照片 10–14 秒，`duck` 为 0.3。`duckAt` 在 3.5 秒为 1，4.0 到 10.0 秒为 0.3，10.5 秒为 1。

### 1.3 播放器

`apps/web/src/player/PlaybackController.ts`：

- 每帧对当前页正在播放的视频：`muted` = 用户静音，或 V 为 0，或该素材 `muted`；否则音量 = 主音量 × `videoSoundGain`。
- 保留“暂停状态下音量不低于 0.05”的处理（部分安卓 WebView 会丢音轨）。
- 配乐音量每帧取 `bgmGainAt`，自动带上压低。

### 1.4 导出 MP4

`apps/web/src/create/export/audio.ts`：有配乐就混配乐，V 大于 0 就混视频原声，两路可以同时存在。配乐串两个增益节点，一个走首尾淡入淡出的折线，一个走压低的折线；两条都是分段线性，相乘的结果与播放一致。

### 1.5 制作器

编辑内容（`EditorDoc`）新增三项，都进撤销栈：

| 字段 | 新建时 | 说明 |
| --- | --- | --- |
| `musicVolume` | 1 | 配乐音量 |
| `videoVolume` | 1 | 视频原声音量 |
| `duckMusic` | true | 视频有声音时把配乐压到 30% |

单个视频的静音记在页的编排里（`ItemPlan.muted`），随 `generator.plan` 保存和还原。

界面：

- 设置面板的配乐一栏：
  - “配乐音量”滑块，0 到 100%，步长 5%。选了配乐才显示。
  - “视频原声音量”滑块，0 到 100%，步长 5%。入选素材里有带声音的视频才显示。
  - 复选框“视频有声音时自动压低配乐”。选了配乐且有带声音的视频才显示；原声音量为 0 时禁用。
- “本页”面板：视频页且该视频有声音时，有复选框“本页视频静音”。
- 连续拖动同一个滑块，间隔不超过 1 秒的合并成一步撤销。
- 三个整片音量设置不重新生成预览，直接改当前预览的清单，拖滑块时边播边听。

打开已有的包时的还原规则：

| 编辑内容 | 取值 |
| --- | --- |
| `musicVolume` | `bgm.volume`，缺省 1 |
| `videoVolume` | 有效原声音量 V（所以 0.3 及更早、带配乐的包是 0，视频保持静音） |
| `duckMusic` | 没有 `bgm.duck` 时为 true；有时看它是否小于 1 |

选“不用配乐”保存的包里没有 `bgm`，重新打开后配乐音量和压低开关回到默认值。

### 1.6 已知限制

- 压低比例（30%）和过渡时间（0.5 秒）固定，界面不能调。
- 混音不加限幅器。原声 100% 加配乐 30% 一般不会破音；把两者都开到 100% 并关掉压低时可能破音。

### 1.7 验收

- 新建：1 段有声视频 + 几张照片 + 默认配乐。预览里照片页配乐正常，视频页能听到原声且配乐明显变小。保存后的包在播放器里、导出的 MP4 里听感一致。
- 打开一个 0.3 的旧包（有配乐、有视频）：原声音量显示 0%，视频仍静音；不改直接保存，播放结果与原来相同。
- 用 v0.5.0 播放器打开 0.4 的包：提示版本不支持，不崩溃。
- 安卓真机：配乐和视频原声同时出声。

## 2. 转码输出的 H.264 级别

### 2.1 现象和推断

- `2026-01-17 回忆.qyp` 里的 `media/m009.mp4` 在 vivo V2111A（Android 11，WebView 是 Chrome 83）上提示“无法读取或解码”。
- 这个文件是转码得到的，清单记为 `avc1.640032`（High Profile，级别 5.0），画面只有 1080×608。源文件是 `avc1.4d401f`（Main，级别 3.1）。
- 导出 MP4 时已经指定了 `avc1.640028`（级别 4.0），Chrome 的硬件编码器仍然写成 5.0。所以只指定编码串不够。
- 推断：旧手机的硬件解码器按级别判断能不能解，看到 5.0 就拒绝。**这只是推断，要先在真机上证实。**

### 2.2 先验证

1. 从包里取出 `media/m009.mp4`，用 `patchAvcLevel` 把级别改成码流实际满足的最低级别，得到第二个文件。
2. 在真机上用 adb 连 WebView 的 DevTools（做法见 [`dev-0.5.1.md`](./dev-0.5.1.md) 第 1 节），分别用 `video` 元素加载两个文件，记录 `error.code` 和能否出画面。
3. 原文件失败、改过的成功：推断成立。其他结果：级别改写不会让文件更差（只在新级别更低时才改），但要另行确认是不是级别的问题。

这一版写代码时手机没有连上电脑，第 2 步还没有在 vivo 上做过。改写逻辑有单元测试，真机对比留到下次插上手机。

### 2.3 修法：把级别改写成码流实际满足的最低级别

`apps/web/src/create/transcode/avcLevel.ts`，纯函数。

`minimalAvcLevel`：从 3.0、3.1、3.2、4.0、4.1、4.2 里选最低的一个，同时满足：

- 每帧宏块数不超过该级别的 MaxFS。
- 每秒宏块数不超过 MaxMBPS。
- 参考帧数 × 每帧宏块数不超过 MaxDpbMbs。
- 平均码率不超过该级别 MaxBR 的一半（High Profile 的 MaxBR 再乘 1.25），留出峰值余量。

级别表（H.264 标准表 A-1）：

| 级别 | MaxMBPS | MaxFS | MaxDpbMbs | MaxBR（kbps） |
| --- | --- | --- | --- | --- |
| 3.0 | 40500 | 1620 | 8100 | 10000 |
| 3.1 | 108000 | 3600 | 18000 | 14000 |
| 3.2 | 216000 | 5120 | 20480 | 20000 |
| 4.0 | 245760 | 8192 | 32768 | 20000 |
| 4.1 | 245760 | 8192 | 32768 | 50000 |
| 4.2 | 522240 | 8704 | 34816 | 50000 |

`patchAvcLevel`：

- 按盒子层级找到 `moov` 里的 `avcC`，只把 `moov` 读进内存。
- 解析 SPS 取 `profile_idc`、`level_idc`、`max_num_ref_frames`。
- 算出的级别低于现有级别时，改写 `avcC` 的第 4 个字节和每个 SPS 的第 4 个字节，其余字节不动。
- 这些情况原样返回：找不到 `avcC`；SPS 解析不了；profile 不是 Baseline、Main、High；算出的级别不低于现有级别。

只处理本工具自己编码出来的文件，帧率按上限 30 计算，码率按转码和导出的设定值（8 Mbps）计算。

接入位置（验证通过后）：

- 转码：`transcode/workers.ts`，编码完成后、探测文件信息前。清单里的 `mimeType` 随之是新级别。
- 导出 MP4：`export/run.ts`，写出文件前。
- 打开旧包：`editor/restore.ts`，对转码过的 H.264 视频改写并更新 `mimeType`。已有的影片重新打开再保存即可修好。

### 2.4 验收

- 重新打开 `2026-01-17 回忆.qyp` 并保存，新包里 `m009.mp4` 的 `mimeType` 是 `avc1.64001f`，在真机上能播放且有声音。
- 电脑上 Chrome 和 Firefox 播放正常。

## 3. 草稿自动保存与恢复

### 3.1 行为

- 只在电脑环境启用。
- 编辑内容有未保存的更改时，停止操作 2 秒后把当前内容写进浏览器的 IndexedDB。写入期间又有修改，写完后再写一次。
- 回到“没有未保存更改”时删除草稿：保存成功、新建、打开别的影片、撤销回到已保存位置。
- 启动制作器时发现草稿，弹对话框询问是否恢复。
  - 恢复：素材、设置、单页修改、配乐、音量都回来，状态是“有未保存更改”。撤销历史不恢复。
  - 丢弃：删除草稿。
- 存不下（`QuotaExceededError`）：删除不完整的草稿，本次会话停止自动保存，提示一次。
- 同时开两个制作器：用 `navigator.locks` 抢一把名为 `qymaker-draft` 的锁，抢到的页面负责读写草稿，另一个既不提示恢复也不写。浏览器没有 `navigator.locks` 时视为抢到。
- 关页面时的未保存提醒保留。

### 3.2 存储结构

数据库 `qymaker-draft`，版本 1，两个对象仓库：

| 仓库 | 键 | 值 |
| --- | --- | --- |
| `meta` | `"current"` | `{version: 1, savedAt, doc}` |
| `blobs` | `blobKey` | 素材或配乐文件（Blob） |

`doc` 是编辑内容去掉所有 Blob 后的 JSON：

- 素材按列表顺序存放，`pages` 里的素材 key 改写成“位置 + 1”，与打开包时的约定一致。
- 每个素材带一个 `blobKey`。同一个文件在整个会话里 `blobKey` 不变，所以没变的文件不会重复写入。
- 导入的配乐也带 `blobKey`；内置曲目只记曲目编号。

写入顺序：先写仓库里还没有的 Blob，再写 `meta`，最后删掉 `meta` 不再引用的 Blob。任何一步中断，旧的 `meta` 和它引用的 Blob 都还完整。

恢复时发现引用的 Blob 缺失，或 `version` 不认识，视为草稿损坏，直接删除，不提示。

### 3.3 代码组织

| 文件 | 内容 |
| --- | --- |
| `apps/web/src/create/draft/serialize.ts` | 编辑内容与草稿记录互转的纯函数 |
| `apps/web/src/create/draft/store.ts` | 接口 `DraftStore` 和 IndexedDB 实现、内存实现（测试用） |
| `apps/web/src/create/draft/autosave.ts` | 写入、读取、清除的流程（不含界面） |
| `apps/web/src/create/draft/useDraftAutosave.ts` | 去抖、加锁、与界面的连接 |
| `apps/web/src/create/editor/state.ts` | `loadDraft`：同 `loadEditor`，但状态是“有未保存更改” |

### 3.4 验收

- 加 3 个素材、改标题、改一页的时长，等 3 秒，直接关掉标签页。重新打开制作器，弹出恢复提示；点恢复后内容都在，显示有未保存更改。
- 保存成功后关掉再开：不弹。
- 点丢弃后关掉再开：不弹。
- 桌面制作器里重复第一条。
